# AI DIRECTOR 2 — AUTONOMOUS END-TO-END RECOVERY

## ГЛАВНАЯ ЦЕЛЬ

Необходимо автономно довести существующий проект **AI Director 2** до получения и отображения **реальных данных Wildberries** хотя бы для одного уже созданного кабинета:

**`seller Sergey`**

Сейчас этот кабинет находится в неисправном состоянии: вместо нормальных показателей отображаются ошибки/данные отсутствуют.

### Критерий успеха

Работа считается успешно завершённой только тогда, когда существующий кабинет `seller Sergey` сможет пройти максимально полный реальный путь:

**Wildberries API → загрузка → raw → normalize → расчётное ядро → DB → API → frontend**

и в интерфейсе AI Director 2 будут отображаться **подтверждённые данные Wildberries**, относящиеся именно к этому кабинету.

Не подставлять mock/demo/fixture данные для имитации успеха.

# 10. ЕСЛИ ВСТРЕТИЛСЯ HTTP 429

Это особенно важно.

Если Wildberries возвращает:

`429 Too Many Requests`

не считать это автоматически ошибкой кода.

Проверить:

- какой endpoint;
- сколько запросов выполняется;
- порядок запросов;
- rate limit;
- повторные запросы;
- существующие raw данные;
- предыдущие логи;
- уже проведённые исследования.

**Не делать бессмысленные повторные live-запросы.**

Если данные уже сохранены в raw — используй их для диагностики.

Если live-проверка невозможна из-за rate limit, это должно быть явно отражено в финальном отчёте.

Не подставляй fake data для обхода 429.

# 14. ФИНАНСОВАЯ АРХИТЕКТУРА

Если данные проходят через финансовую часть:

`raw → normalized → derived → Finance Kernel → report/frontend`

Проверить:

- деньги только `Decimal`;
- нет финансового `float`;
- нет неправильного `abs()`;
- нет двойного учёта;
- orders не подменяют buyouts;
- Finance Detail используется согласно архитектуре;
- себестоимость берётся из предусмотренных настроек;
- налог берётся из предусмотренных настроек;
- прибыль рассчитывается в Finance Kernel;
- frontend/report не пересчитывают финансовые значения;
- AI не рассчитывает финансы.

Принцип:

**одна метрика — один владелец.**
