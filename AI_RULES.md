# AI_RULES — WB AI Agent (v3)

## 0) Главная цель
Мы развиваем новую архитектуру **v3** НЕ ломая рабочую версию (**src/**). Любые изменения должны быть безопасны и обратимы.

## 1) Границы изменений (ОБЯЗАТЕЛЬНО)
Разрешено:
- создавать и менять файлы **только внутри `v3/`**
- создавать docs внутри `v3/` (README, notes)

Запрещено без явного разрешения:
- менять **`src/`** (любые файлы)
- менять **`.github/`** и workflows
- удалять/перемещать существующие файлы
- массовый рефакторинг “по красоте”

Если нужно изменить что-то вне `v3/` — сначала объясни почему и спроси подтверждение.

## 2) Безопасность данных (мультикабинеты)
- Каждый селлер живёт в `cabinets/<seller_id>/`
- Нельзя смешивать данные разных селлеров в одном файле/папке.
- Никаких ключей/токенов в репозитории. Секреты — только через env vars или локальные ignored файлы.
- Любые артефакты (facts/metrics/pdf/logs) должны храниться внутри кабинета, например:
  `cabinets/<seller_id>/artifacts/...`

## 3) Поведение агента при разработке
Перед тем как писать код:
1) Коротко опиши план (3–7 пунктов).
2) Назови файлы, которые изменишь/создашь.
3) Затем предоставь diff или полный код новых файлов.

Если задача неясна — НЕ задавай много вопросов. Сделай разумные допущения и явно их перечисли.

## 4) Стандарты кода (Python)
- Python 3.11
- Минимум зависимостей
- Явные типы там, где не мешают
- Понятные сообщения об ошибках
- Логи через стандартный `logging`
- Не “магия”: предпочтение простым функциям и маленьким модулям

## 5) Quality Gate (чтобы отчёт не был пустым)
Если данных нет:
- не генерируй “фантазийные” цифры
- возвращай понятный статус: что отсутствует и что сделать пользователю
- CLI должен завершаться без падений, с кодом 0/1 по ситуации и с сообщением

## 6) Git hygiene
- Не добавляй в git: отчёты, pdf, xlsx, артефакты, логи, __pycache__
- Если создаёшь новые папки под артефакты — добавляй `.gitkeep`
