# План: Редизайн отчёта — Unit-экономика + воронка по SKU

На основе ТЗ от Kimi и запроса пользователя. Цель — 2-страничный отчёт: Hero → Действия → ТОП SKU (unit-экономика + воронка) → Сводка.

## Ключевой инсайт из Kimi

Finance API (`reportDetailByPeriod`) возвращает **per-SKU строки** с:
- `wb_commission` — комиссия WB по SKU
- `logistics_amount` — логистика по SKU
- `acquiring` — эквайринг по SKU
- `realized_sales_revenue` — выручка по SKU

**Только `storage` и `deductions`** — агрегатные (отдельные строки без nm_id), распределяем пропорционально выручке.

## Изменения

### 1. Snapshot — добавить per-SKU rows

**Файл:** `wb_api_core/snapshot.py`

Reconcile_result содержит per-SKU `rows` в `live_operational.*` и `finance_final_daily.rows`. Snapshot-builder их выбрасывает. Нужно добавить:

```python
# live_operational.sales — добавить rows
"sales": { ..., "rows": live_sales.get("rows", []) }
# аналогично для orders, stocks, ads
# finance_final_daily — добавить rows
"finance_final_daily": { ..., "rows": finance_rows }
```

Также в reconcile.py сохранить per-SKU funnel rows из cabinet_commerce raw products:
```python
funnel_daily["sku_rows"] = [{"nm_id": ..., "seller_sku": ..., "views": ..., "cart": ..., "orders": ..., "buyouts": ...}]
```

### 2. Новый builder: `_build_sku_detail_section()`

**Файл:** `report_v2/builders/report_payload_builder.py`

Собирает per-SKU данные для ТОП SKU.

**Входные данные:**
- `snapshot.live_operational.sales.rows` — per-SKU выручка (nm_id, seller_sku, quantity, amount)
- `snapshot.live_operational.orders.rows` — per-SKU заказы
- `snapshot.finance_final_daily.rows` — per-SKU комиссия, логистика, эквайринг
- `snapshot.funnel_daily.sku_rows` — per-SKU воронка
- `snapshot.live_operational.ads.rows` — per-SKU реклама
- `cogs_map` — себестоимость

**Логика для каждого SKU:**
1. Агрегация sales rows по nm_id → выручка, количество выкупов
2. Агрегация orders rows по nm_id → количество заказов
3. Из finance rows (row_group="sale") по nm_id → `wb_commission`, `logistics_amount`, `acquiring` ТОЧНЫЕ
4. Из finance rows (без nm_id, row_group="storage"/"deductions") → aggregate storage/deductions
5. Распределение storage/deductions пропорционально выручке SKU
6. Агрегация ads rows по nm_id → рекламный расход
7. `sku_profit = revenue - cogs - |commission| - |logistics| - |acquiring| - |storage_share| - |deductions_share| - ads_spend`
8. `sku_margin = profit / revenue * 100`
9. `sku_share = revenue / total_revenue * 100`

**Выход — список SKU карточек:**
```python
{
    "nm_id": "898642228",
    "seller_article": "ART-123",
    "orders_count": 4,
    "buyouts_count": 2,
    "revenue": 11400,
    "cogs": 2400,
    "commission": 256.98,
    "logistics": 166.40,
    "acquiring": 403.84,
    "storage_share": 12.50,
    "deductions_share": 450.00,
    "ads_spend": 259.78,
    "profit": 7451.50,
    "margin_pct": 65.4,
    "share_pct": 45.2,
    "funnel": { "views": 463, "clicks": 65, "ctr_pct": 14.04, "cart": 12, "orders": 4, "buyouts": 2, "cr_cart_pct": 18.5, "cr_order_pct": 33.3, "cr_buyout_pct": 50.0 },
    "alert": "..."
}
```

**Сортировка:** по profit DESC (ТОП прибыльные). Убыточные (profit < 0) — отдельный список.
