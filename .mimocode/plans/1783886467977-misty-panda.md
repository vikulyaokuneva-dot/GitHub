# Исправление: запрет fallback для финансовых данных

## Проблема

Отчёт ИИ Директора за 11.07.2026 показывает финансовые данные из **устаревшего snapshot** (27 июня) вместо актуальных данных за 11 июля. Причины:

1. **`run_daily.py`** (строки 88-102): fallback на `latest_finance.json` без проверки даты
2. **`artifacts.py`** (строки 224-236): fallback `finance_final_daily` из `latest_successful.json` без проверки даты
3. **`daily_metrics_stage.py`** (строки 758-796): fallback финансовых KPI из snapshot когда kernel вернул пустоту

**Правильные данные за 11.07.2026 (из WB отчёта):**
- Продажи: 3 шт., розница 1 180 ₽, реализовано 688 ₽
- К перечислению: 719,48 ₽
- Комиссия WB (без НДС): -66,11 ₽
- Логистика (AK): 534,78 ₽
- Хранение: 24,30 ₽
- Эквайринг (AC): 27,52 ₽
- Возвраты: 0
- Компенсация перевозки (BF): 829,34 ₽

## Решение

Запретить fallback для финансовых данных. Если данных за нужную дату нет — показать что финансовые данные недоступны.

## Файлы для изменения

### 1. `wb_api_core/run_daily.py` (строки 88-102)

**Было:** fallback на `latest_finance.json` когда `finance_final_daily` недоступен

**Стало:** удалить блок fallback (строки 88-102). Если `finance_final_daily` не доступен — оставить как есть (с None значениями). Добавить предупреждение что финансовые данные за эту дату недоступны.

```python
# УДАЛИТЬ строки 88-102 (fallback на latest_finance.json)
# Вместо этого, если finance_daily не available, добавить предупреждение:
if isinstance(finance_daily, dict) and not finance_daily.get("available"):
    warnings = list(reconcile_result.get("warnings", []) or [])
    warnings.append({
        "code": "finance_final_unavailable_for_date",
        "message": f"Finance data not available for {resolved_run_date}. No fallback applied.",
        "level": "warning",
        "block": "finance_final",
    })
    reconcile_result["warnings"] = warnings
```

### 2. `wb_api_core/artifacts.py` (строки 224-236)

**Было:** fallback `finance_final_daily` из кэша `latest_successful.json`

**Стало:** удалить блок fallback финансовых данных (строки 224-236). Оставить только fallback для live операций (orders, sales, stocks, ads).

```python
# УДАЛИТЬ строки 224-236 (finance_final_daily fallback из cached_snapshot)
# Финансовые данные НЕ должны fallback из кэша
```

### 3. `v3/pipeline/daily_metrics_stage.py` (строки 758-796)

**Было:** fallback финансовых KPI из snapshot когда kernel вернул пустоту

**Стало:** удалить блок fallback (строки 758-796). Если kernel вернул пустые данные — показать что финансовые данные недоступны. НЕ использовать snapshot как источник.

```python
# УДАЛИТЬ строки 758-796 (fallback из snapshot_finance_final_daily)
# Вместо этого, если financial_kpi пустой, добавить диагностику:
if not financial_kpi.get("revenue") and not financial_kpi.get("seller_payout"):
    financial_kpi["financial_status"] = "unavailable"
    financial_kpi["is_partial"] = True
    financial_kpi["net_profit_partial"] = True
    print(f"[financial_kpi] No financial data available for {run_date}. Snapshot fallback disabled.")
```
