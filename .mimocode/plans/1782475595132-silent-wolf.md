# План: Секция «Динамика продаж» в дневном отчёте V2

## Задача
Добавить в PDF-отчёт секцию, показывающую сравнение ключевых метрик: сегодня / вчера / неделю назад.

## Что уже есть
- **История**: `cabinets/{seller}/history/daily/{date}/` — ежедневные снапшоты с `facts.json` (KPI: revenue, profit, buyouts, ads_spend) и `metrics.json`
- **Индекс**: `cabinets/{seller}/history/history_index.json` — реестр всех снапшотов с KPI-сводкой
- **Загрузчик**: `v3/history/trend_anomalies.py:load_recent_history()` — загружает N последних снапшотов с payload
- **Сравнение SKU**: `v3/metrics/sku_daily_dynamics_builder.py` — vs_previous_day и vs_7d_avg (но только на уровне SKU, не агрегат)
- **PDF**: секции рендерятся в `report_v2/renderers/pdf_renderer_v2.py:write_report_pdf_v2()`, порядок: hero → actions → commerce → profit → funnel → ads → TOP SKU → loss SKU → search

## Что нужно сделать

### 1. Builder: `build_sales_dynamics_section_v2()` — `report_v2/builders/report_payload_builder.py`

Новая функция, принимает `seller_id`, `run_date`, `repo_root`:
- Читает `history_index.json`
- Находит снапшоты за даты: `run_date`, `run_date - 1 день`, `run_date - 7 дней`
- Для каждой даты берёт KPI из индекса: revenue, profit, buyouts, ads_spend
- Считает дельты: vs вчера (абс + %), vs 7 дней назад (абс + %)
- Возвращает секцию типа:
```json
{
  "title": "Динамика продаж",
  "rows": [
    {"label": "Метрика", "today": "...", "yesterday": "...", "week_ago": "...", "vs_yesterday": "+10%", "vs_week": "-5%"},
    ...
  ],
  "available": true
}
```
- Метрики: Выручка, Прибыль, Выкупы, Расход на рекламу, ROI (если доступен)
- Если данных нет — показывает «н/д»

### 2. Schema: добавить тип `SalesDynamicsSectionV2` — `report_v2/contracts/report_payload_schema.py`

Минимальный тип для секции (title, rows, available). Или просто dict если不想 расширять schema.

### 3. Включить в payload — `report_payload_builder.py:build_report_payload_v2()`

Добавить вызов `build_sales_dynamics_section_v2()` и положить результат в payload под ключом `sales_dynamics_section`. Функция принимает `seller_id` и `run_date` из meta.

### 4. Renderer: отрисовка таблицы — `pdf_renderer_v2.py`

Добавить блок после `profit_section` (перед funnel). Таблица 5 колонок:
| Метрика | Сегодня | Вчера | 7 дн. назад | Δ вчера | Δ 7 дн. |

Стиль аналогичен `_display_rows_table`. Цветовая индикация: зелёный рост, красный спад.

### 5. Файлы для изменения

| Файл | Что менять |
|---|---|
| `report_v2/builders/report_payload_builder.py` | Новая функция `build_sales_dynamics_section_v2()`, вызов в `build_report_payload_v2()` |
| `report_v2/renderers/pdf_renderer_v2.py` | Блок отрисовки секции после profit_section |
| `report_v2/contracts/report_payload_schema.py` | Опционально: добавить тип |

### 6. Альтернативный подход (проще)

Вместо чтения history_index.json из builder — передавать данные dynamics из `daily_output_stage.py`, который уже имеет доступ к истории. Тогда builder просто форматирует данные, а загрузка — на уровне pipeline.

**Рекомендую вариант 1** (builder сам читает индекс) — он автономнее и не зависит от pipeline.
