# План: P0 фичи для ежедневного отчёта

## Цель
Превратить ежедневный отчёт из "среза данных" в "инструмент управления" — главный экран с действиями, цветовые сигналы, потери дня.

## Фичи P0

### 1. Сводка "Что делать сегодня" (Hero section)
**Где:** Вместо текущего hero_section (первый экран отчёта)
**Что показывать:**
- Дата + кабинет
- 3-5 алертов с приоритетом:
  - Возвраты выше нормы
  - Реклама без заказов (сумма потерь)
  - A-SKU с 0 остатком
  - Маржа ниже 30%
  - Убыточные SKU
- Блок "Что делать сегодня" — 3-5 конкретных действий

**Данные из:** snapshot (finance, orders, sales, stocks, ads)

### 2. Цветовая индикация (🔴🟡🟢)
**Где:** На всех ключевых метриках
**Правила:**
- 🔴 Красный: возвраты > 2 шт, реклама без заказов > 100₽, A-SKU 0 остатка, маржа < 20%
- 🟡 Жёлтый: маржа 20-30%, CTR < 3%, запасы > 60 дней, B-SKU 0 остатка
- 🟢 Зелёный: всё в норме

**Реализация:** Добавить `status` поле к каждому display_row, renderer рисует цветной индикатор

### 3. Потери дня
**Где:** Отдельный блок после сводки
**Что считать:**
- Реклама без заказов (₽)
- Убыточные SKU (если есть)
- Переплата логистики (если данные есть)
- Итого: "Сегодня потеряно X ₽"

**Данные из:** finance, ads, sku_detail

### Файлы для изменения
| Файл | Что менять |
|------|-----------|
| `report_v2/builders/report_payload_builder.py` | Новый `_build_actions_summary()`, обновить `_build_hero_section()` |
| `report_v2/renderers/pdf_renderer_v2.py` | Новая отрисовка hero с цветами, блок потерь |
| `report_v2/contracts/report_payload_schema.py` | Опционально: новые типы |

## Верификация
1. `python -m v3.entry daily --seller seller_001 --date 2026-06-25`
2. Проверить что hero показывает алерты с цветами
3. Проверить что блок "Что делать" содержит конкретные действия
4. Проверить что "Потери дня" считает правильно
