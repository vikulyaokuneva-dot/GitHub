- Валидирует контракт (seller_id, run_date, required keys)
- Строит core_report_payload с financial_kpi, daily_kpi, live_operational

**4. "Чистка мёртвого веса" — преждевременна:**
- Нужно СНАЧАЛА подтвердить что v3 работает, И ТОЛЬКО ПОТОМ удалять src/, pipeline/ и т.д.
- Claude Code ставит чистку 4-й задачей — это правильно

## План реализации

### Фаза 0: Зафиксировать аудит (СЕЙЧАС)
- Коммит текущего состояния аудит-слоя
- Все изменения в audit/ зафиксированы

### Фаза 1: Live прогон wb_api_core на данных кабинета
**Цель**: Убедиться что wb_api_core сам по себе работает и данные собираются корректно.

**Шаги:**
1. Запустить `python -m wb_api_core.run_daily --seller seller_001 --date 2026-06-19`
2. Проверить артефакты: `cabinets/seller_001/artifacts/wb_api_core/2026-06-19/`
   - snapshot.json — какие данные собраны, available/unavailable
   - debug.json — статус каждого эндпоинта
   - reconciled_rows.json — сырые строки
3. Если эндпоинт 403/429 — проверить fallback на latest_successful.json
4. Документировать что работает и что нет

**Файлы для проверки:**
- `wb_api_core/run_daily.py` — точка входа
- `wb_api_core/loaders.py` — загрузка с API
- `wb_api_core/artifacts.py` — запись артефактов

### Фаза 2: Live прогон v3 через core_snapshot путь
**Цель**: Запустить v3.entry НЕ через прямой API, а через core_report_bridge (путь B). Сравнить данные обоих путей.

**Шаги:**
1. Убедиться что snapshot из фазы 1 существует
2. Запустить `python -m v3.entry daily --seller seller_001 --date 2026-06-19`
3. Проверить: daily_output_stage находит и читает snapshot?
4. Проверить: core_report_bridge строит core_report_payload корректно?
5. Проверить: PDF генерируется?

**Ключевой файл:** `v3/pipeline/daily_output_stage.py:78` — `resolve_core_snapshot_paths()`

**Сравнительный лог (обязательно):**
В `v3/pipeline/daily_output_stage.py` (или отдельный tmp-скрипт) добавить блок, который:
- Извлекает ключевые числа из **пути A** (daily_input_stage → context)
- Извлекает ключевые числа из **пути B** (core_report_bridge → snapshot)
- Выводит таблицу сравнения:

```
=== DELTA: путь A vs путь B ===
Метрика          | Путь A (input_stage) | Путь B (snapshot) | Delta
-----------------|---------------------|-------------------|------
revenue          | 79447.50            | 79447.50          | 0.00
orders_count     | 51                  | 51                | 0
buyouts_count    | 26                  | 26                | 0
commission       | -832.80             | -832.80           | 0.00
logistics        | 23653.70            | 23653.70          | 0.00
returns_qty      | 11                  | 11                | 0
net_profit       | 24944.93            | 24944.93          | 0.00
```

- Флаг `DELTA_NONZERO` если хотя бы одно расхождение > 0.01
- Если delta > 0 — причина: разные формулы, разные источники, или丢失 данных

**Реализация:** Добавить функцию `_compare_data_paths(context, core_report_payload)` в `daily_output_stage.py` и вызвать перед рендерингом. Или вынести в tmp-скрипт `tmp_compare_api_paths.py` (проще, без рисков для production).
