# План: Отделение слоя Audit от API слоя

## Цель
Слои audit и api (v3) не должны быть архитектурно связаны. При изменениях в api-слое файлы audit должны оставаться нетронутыми и работоспособными.

## Текущие зависимости audit от внешних модулей

```
audit/
├── audit_facts_builder.py
│   ├── src/metrics.py          ← calc_ads_metrics, calc_financial_metrics, calc_funnel_metrics
│   ├── src/sku_performance_analyzer.py  ← analyze_sku_performance
│   ├── shared/logistics_reference.py
│   └── shared/wb_logistics_regions.py
├── run_audit.py
│   └── src/pdf_report.py       ← markdown_to_simple_pdf
└── audit_ozon/runner.py
    └── src/pdf_report.py       ← markdown_to_simple_pdf
```

## Проблема
При изменении `src/metrics.py`, `src/pdf_report.py` или `shared/` модулей audit может сломаться.

## Решение: копирование зависимостей внутрь audit

### Стратегия
Создать внутри `audit/` собственные копии необходимых модулей:
- `audit/lib/metrics.py` — копия `src/metrics.py` + `src/cogs.py`
- `audit/lib/pdf_report.py` — копия `src/pdf_report.py`
- `audit/lib/logistics_reference.py` — копия `shared/logistics_reference.py`
- `audit/lib/wb_logistics_regions.py` — копия `shared/wb_logistics_regions.py`
- `audit/lib/sku_performance_analyzer.py` — копия `src/sku_performance_analyzer.py`

### Файлы для изменения

| Файл | Изменение |
|------|-----------|
| `audit/lib/__init__.py` | Создать (пустой) |
| `audit/lib/metrics.py` | Скопировать из `src/metrics.py`, заменить импорт `src.cogs` → `audit.lib.cogs` |
| `audit/lib/cogs.py` | Скопировать из `src/cogs.py` |
| `audit/lib/pdf_report.py` | Скопировать из `src/pdf_report.py` |
| `audit/lib/logistics_reference.py` | Скопировать из `shared/logistics_reference.py` |
| `audit/lib/wb_logistics_regions.py` | Скопировать из `shared/wb_logistics_regions.py`, заменить импорт `shared.logistics_reference` → `audit.lib.logistics_reference` |
| `audit/lib/sku_performance_analyzer.py` | Скопировать из `src/sku_performance_analyzer.py` |
| `audit/audit_facts_builder.py` | Заменить импорты: `src.metrics` → `audit.lib.metrics`, `src.sku_performance_analyzer` → `audit.lib.sku_performance_analyzer`, `shared.logistics_reference` → `audit.lib.logistics_reference`, `shared.wb_logistics_regions` → `audit.lib.wb_logistics_regions` |
| `audit/run_audit.py` | Заменить импорт: `src.pdf_report` → `audit.lib.pdf_report` |
| `audit/audit_ozon/runner.py` | Заменить импорт: `src.pdf_report` → `audit.lib.pdf_report` |

### Шаги реализации

1. **Создать `audit/lib/` директорию**
2. **Скопировать модули** (без изменений логики):
   - `src/cogs.py` → `audit/lib/cogs.py`
   - `src/metrics.py` → `audit/lib/metrics.py` (поправить импорт cogs)
   - `src/sku_performance_analyzer.py` → `audit/lib/sku_performance_analyzer.py`
   - `src/pdf_report.py` → `audit/lib/pdf_report.py`
   - `shared/logistics_reference.py` → `audit/lib/logistics_reference.py`
   - `shared/wb_logistics_regions.py` → `audit/lib/wb_logistics_regions.py` (поправить импорт)
3. **Обновить импорты в audit/**:
   - `audit/audit_facts_builder.py`
   - `audit/run_audit.py`
   - `audit/audit_ozon/runner.py`
4. **Проверить работоспособность**: запустить `python run.py --mode audit`

### Итоговая структура audit/


## Верификация
1. `python run.py --mode audit --seller seller_001` — должен отработать без ошибок
2. Проверить что `audit/output/` содержит facts.json, .md, .pdf
3. Убедиться что изменения в `src/metrics.py` или `v3/` не ломают audit
