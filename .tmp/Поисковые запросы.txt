Аналитика поисковых запросов по вашим товарам
Отчёт Поисковые запросы по вашим товарам содержит:

запросы, по которым покупатели искали ваши товары и переходили в карточки
данные о том, на каких местах в поисковой выдаче находились ваши карточки и по каким причинам
Анализ поисковых запросов — основа SEO-оптимизации на маркетплейсах. С помощью анализа можно понять, по каким ключевым фразам ранжируются запросы, а также какие запросы приводят целевую аудиторию и конвертируются в заказы.

WB API Поисковых запросов по вашим товарам подходит для всех моделей продаж. Используйте эти методы, чтобы:

Отслеживать, как меняются позиции товаров в поиске по ключевым запросам

Анализировать факторы ранжирования, чтобы понимать, какие параметры влияют на место карточки в результатах поиска и как их можно улучшить

Оценивать видимость товаров — вероятность того, что покупатель увидит вашу карточку в поиске

Формировать семантическое ядро, чтобы находить новые перспективные запросы, по которым уже показываются товары, и отсеивать запросы, которые не приводят к заказам

Анализировать конверсии по запросам, чтобы отслеживать, как часто пользователи переходят в карточку из поиска, добавляют товар в корзину и оформляют заказы

Оптимизировать рекламные кампании за счёт расширения семантики успешными запросами и отсечения нецелевого трафика

В разделе Поисковые запросы по вашим товарам WB API пять методов. Чтобы выбрать подходящий, ориентируйтесь на свою задачу.

Методы Поисковых запросов по вашим товарам доступны только при наличии подписки Джем. Так же, как и в методах Воронки продаж, данные возвращаются максимум за последние 365 дней с момента выполнения запроса. Чтобы проанализировать более долгие периоды, рекомендуем регулярно сохранять полученные данные

Основная страница
Метод POST /api/v2/search-report/report формирует сводную аналитику о выдаче товаров в результатах поиска.

Используйте метод, чтобы мониторить эффективность SEO-оптимизации:

оценивать эффективность всего семантического ядра
выявлять карточки, которые находятся в топе поисковой выдачи и генерируют основную долю продаж
сравнивать различные периоды, чтобы видеть динамику видимости карточек
учитывать региональные особенности, которые влияют на позиции в поиске — например, распределение заказов по регионам и среднее время доставки
Методы Поисковых запросов по вашим товарам не хранят информации о сроках доставки товаров по регионам. Чтобы отследить влияние этих изменений на видимость карточек товаров в результатах поиска, рекомендуем использовать методы Истории остатков

Пагинация по группам
Метод POST /api/v2/search-report/table/groups возвращает данные по товарам, сгруппированным по предметам, брендам или ярлыкам.

Используйте метод, чтобы решать задачи категорийного управления:

выявлять товары, которые теряют позиции в поиске, внутри группы
получать срезы по товарам в группе для анализа их поисковой эффективности
измерять динамику роста поисковых позиций и заказов у новых товаров
находить товары, которые нужно оптимизировать — например, те, что вылетели из топ-100
Пагинация по товарам в группе
Метод POST /api/v2/search-report/table/details возвращает данные по конкретным товарам внутри выбранной группы.

Позиции товара в результатах поиска персонализированы и могут различаться для разных покупателей. В методах Поисковых запросов по вашим товарам используется средняя позиция товара по всем показам за период. Это позволяет сгладить индивидуальные отклонения и оценить реальное ранжирование

Используйте метод, чтобы решать оперативные задачи:

анализировать эффективность отдельных товаров — например, товаров с аномально низкой конверсией или видимостью
отслеживать динамику позиций и переходов по товарам
сравнивать товары внутри группы по ключевым метрикам: позициям, переходам, добавлениям в корзину, заказам
контролировать результаты изменений в карточках — например, после обновления цены или запуска рекламы через WB Продвижение
Методы Поисковых запросов по вашим товарам не хранят историю изменений карточки, например, цены, описания или обложки товара. Чтобы отследить, как эти изменения влияют на показы товара в результатах поиска, рекомендуем:
• сохранять информацию об изменениях карточек товаров с указанием дат
• сопоставлять сохранённые события с данными API

Поисковые запросы по товару
Метод POST /api/v2/search-report/product/search-texts возвращает топ поисковых запросов, по которым конкретный товар показывался пользователям в результатах поиска.

Используйте метод, чтобы решать задачи расширения семантического ядра:

находить неочевидные запросы, которые вы могли не учесть при первичной SEO-оптимизации карточки
оценивать частотность запросов и текущие позиции товара по каждому из запросов
выявлять новые перспективные фразы для добавления в название, описание или настройки рекламных кампаний
Максимальное количество запросов в ответе метода POST /api/v2/search-report/product/search-texts — 30. Для тарифов Продвинутый и Премиальный — 100

Заказы и позиции по поисковым запросам товара
Метод POST /api/v2/search-report/product/orders возвращает данные о заказах по каждому поисковому запросу для конкретного товара и позициях товара в результатах поиска по этому запросу. Данные отчёта сгруппированы по дням, максимальный интервал — 7 дней.

Используйте метод, чтобы решать задачи оценки коммерческой эффективности запросов:

отслеживать, как изменения в карточках и количество заказов влияют на результаты поиска
определять, какие поисковые фразы влияют на рост или падение заказов
находить дни пикового спроса
оценивать эффективность SEO-оптимизации и рекламных кампаний, чтобы спрогнозировать количество заказов
CSV-отчёты Поисковых запросов по вашим товарам
Для работы с большими объёмами данных используйте специализированные CSV-отчёты Поисковых запросов по вашим товарам:

SEARCH_QUERIES_PREMIUM_REPORT_PRODUCT — детализированные данные по параметрам поиска по каждому артикулу
SEARCH_QUERIES_PREMIUM_REPORT_GROUP — агрегированная статистика по параметрам поиска по предметам, брендам, ярлыкам
SEARCH_QUERIES_PREMIUM_REPORT_TEXT — данные по текстам поисковых запросов (семантическое ядро)
Данные в отчётах Поисковых запросов по вашим товарам представлены максимум за 365 дней и доступны с подпиской Джем

Чтобы получить CSV-отчёт, соблюдайте порядок действий:

scheme
Шаг 1. Создайте задание на генерацию
Выполните запрос метода POST /api/v2/nm-report/downloads. В теле запроса укажите:

UUID отчёта
тип — например, SEARCH_QUERIES_PREMIUM_REPORT_GROUP
период
уровень детализации
фильтры
Шаг 2. Проверьте статус готовности
Отчёт формируется не сразу. Чтобы проверить статус генерации отчёта, используйте метод GET /api/v2/nm-report/downloads.

Когда статус сменится на SUCCESS, отчёт будет готов. Файлы хранятся 48 часов.

Если вы получили статус FAILED, отправьте запрос POST /api/v2/nm-report/downloads/retry, чтобы сгенерировать отчёт повторно

Шаг 3. Скачайте готовый отчёт
Готовый CSV-отчёт будет сгенерирован в ZIP-архив. Скачайте его с помощью метода GET /api/v2/nm-report/downloads/file/{downloadId}.

Как фильтровать данные
Методы Поисковых запросов по вашим товарам собирают статистику по всем товарам продавца. В зависимости от задачи вы можете настроить выгрузку товаров с помощью фильтров:

currentPeriod и pastPeriod — запрашиваемый период и период для сравнения. Вы можете задать произвольный интервал в пределах доступных дат.
Как можно использовать: сравнить эффективность поисковых запросов в периоды до, во время и после рекламной кампании. Так вы сможете оценить, как продвижение повлияло на видимость товара в результатах поиска.
nmIds — артикулы WB — отбор по конкретным товарам из вашего каталога.
Как можно использовать: проанализировать поисковые запросы только для новинок, чтобы понять, по каким фразам они находят первых покупателей.
brandNames — бренды товаров.
Как можно использовать: сравнить, по каким запросам и с какой конверсией показываются товары одного бренда против другого. По результатам сравнения вы сможете скорректировать стратегию продвижения.
subjectIds — предметы по классификации Wildberries.
Как можно использовать: выгружать топ запросов по товарам категории, чтобы отслеживать перекрёстные фразы в описаниях товаров.
tagIds — ярлыки продавца, которые можно указать в карточке товара.
Как можно использовать: у вас есть товары с ярлыком Сезонный. С помощью фильтра вы сможете оценить видимость этих товаров в результатах поиска перед началом сезона и в его пике. Также вы можете присвоить ярлык рекламным кампаниям и отслеживать их эффективность по этому фильтру.
