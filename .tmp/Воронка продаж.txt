## Что действительно совпало

В ежедневном отчёте WB есть три строки с типом документа «Продажа»:

* SKU `590614192` — одна продажа;
* SKU `551253854` — две продажи.

Итого:

```text
3 продажи
Розничная цена: 1 180 ₽
```

ИИ Директор показывает:

```text
Выкупы: 3 шт.
Сумма выкупов: 1 180 ₽
```

Эта часть корректна.

## Ошибка в выручке

ИИ Директор показывает одновременно:

```text
Сумма выкупов — 1 180 ₽
Выручка от продаж — 7 138 ₽
```

В отчёте WB за 11 июля:

```text
Розничная стоимость продаж — 1 180 ₽
WB реализовал товар с учётом скидок — 688 ₽
К перечислению продавцу — 719,48 ₽
```

Значения `7 138 ₽` в новом отчёте WB нет. Оно совпадает со старым отчётом ИИ Директора за 27 июня.

Следовательно, финансовый блок подтянул устаревший snapshot:

```text
Выручка       7 138 ₽
Комиссия        955,28 ₽
Логистика     2 080,32 ₽
Хранение         40,42 ₽
Эквайринг       255,96 ₽
```

Это практически тот же финансовый набор, который был в предыдущих PDF за 27 июня.

## Возвраты неверны

```

ИИ Директор:

```

Рекомендация построена на неправильных или старых данных. Её нельзя показывать пользователю.

Вероятно, число `2` также пришло из старого финансового snapshot.

## Логистика

WB:

```text
Количество доставок — 3
Количество возвратов — 0
Услуги по доставке — 534,78 ₽
```

ИИ Директор:

```text
Логистика — 2 080,32 ₽
```

Разница:

```text
2 080,32 − 534,78 = 1 545,54 ₽
```

Таким образом, расходы на логистику завышены примерно в 3,9 раза относительно приложенного ежедневного отчёта.

При этом в WB присутствуют отдельные компенсационные операции по перевозке/складским операциям на `829,34 ₽`. Их нельзя автоматически смешивать с обычной логистикой без учёта знака и основания операции.

## Прибыль рассчитана из смешанных периодов

Расчёт ИИ Директора:

```text
7 138
− 955,28
− 2 080,32
− 40,42
− 255,96
− 180
= 3 626,02 ₽
```

Арифметически формула сходится. Но входные значения, кроме себестоимости, взяты из старого финансового набора.

Поэтому:

```text
Чистая прибыль 3 626,02 ₽
Маржа 50,8%
```

не подтверждаются приложенным отчётом WB.

## Воронка продаж

ИИ Директор показывает:

| Показатель      | Значение |
| --------------- | -------: |
| «Клики»         |      339 |
| Корзина         |       39 |
| Заказы          |        4 |
| Выкупы          |        3 |
| Клики → корзина |   11,50% |
| Корзина → заказ |   10,26% |
| Заказ → выкуп   |      75% |

Арифметика верная:

```text
39 / 339 = 11,50%
4 / 39 = 10,26%
3 / 4 = 75%
```

Но `339` следует подписать как:

```text
Переходы в карточку
```

а не «Клики». Это `openCount` из API воронки.

Проверить показы и общий CTR по приложенному ежедневному финансовому отчёту нельзя: в нём нет показов карточек. Для этого нужна выгрузка WB «Воронка продаж по дням» за 11 июля.

## Рекламный блок

Внутренне арифметика почти полностью корректна:

```text
CTR = 64 / 1 038 = 6,17%
CPC = 464,10 / 64 = 7,25 ₽
CPM = 464,10 / 1 038 × 1000 = 447,11 ₽
CPO = 464,10 / 1 = 464,10 ₽
```

Но есть логическое противоречие:

```text
Заказы из рекламы — 1
Выручка из рекламы — 0 ₽
```

Это возможно только если атрибуция денежной суммы ещё не обновилась. Такой заказ нельзя уверенно считать убыточным. В отчёте желательно писать:

```text
Есть 1 рекламный заказ, но WB пока не передал атрибутированную выручку.
Окупаемость рекламы не подтверждена.
```

А не давать категоричный вывод «464 руб. без заказов», потому что ниже указан один заказ.

## ABC-анализ тоже некорректен

Для SKU `551253854`:

```text
Заказы — 0
Выкупы — 2
Выручка — 560 ₽
```

WB действительно показывает две продажи этого SKU, но ноль заказов текущего дня может быть нормальным: продажи относятся к заказам от 4 и 7 июля.

Проблема в том, что отчёт объединяет:

* заказы, созданные 11 июля;
* продажи старых заказов, проведённые 11 июля.

Без пояснения это выглядит как невозможная воронка «0 заказов → 2 выкупа».

## Итоговый диагноз

Отчёт частично работает:

* дата правильная;
* число продаж и их розничная сумма совпали с WB;
* арифметика конверсий и рекламных KPI правильная.

Но финансовая часть отчёта недостоверна:

1. Выручка, комиссия, логистика, хранение и эквайринг взяты из старого snapshot.
2. Показаны два возврата, хотя WB показывает ноль.
3. Из смешанных данных рассчитана неверная прибыль `3 626,02 ₽`.
4. Воронка смешивает сегодняшние заказы с сегодняшними продажами старых заказов.
5. Заголовок «464 руб. без заказов» противоречит показателю «1 заказ из рекламы».

Главная техническая проблема сейчас — fallback на `latest_finance.json` без явной проверки даты snapshot. Старый финансовый snapshot принимается как актуальный для 11 июля. Такой fallback необходимо либо запрещать, либо отображать с пометкой «финансы за другую дату — расчёт прибыли недоступен».
