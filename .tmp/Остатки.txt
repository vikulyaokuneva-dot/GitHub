Остатки на складах WB
Метод POST /api/analytics/v1/stocks-report/wb-warehouses возвращает текущие остатки на складах Wildberries. В отличие от других методов раздела, данные здесь обновляются каждые 30 минут. Это позволяет использовать метод в качестве инструмента для оперативного контроля остатков.

Метод помогает решать задачи быстрого реагирования. Используйте его, чтобы:

оперативно получать данные о количестве товаров на складах WB. Так вы сможете пополнять остатки товаров до того, как они полностью закончатся
отслеживать, как быстро расходуются запасы товаров во время проведения рекламных кампаний
Данные по группам
Метод POST /api/v2/stocks-report/products/groups формирует сводный отчёт по остаткам, сгруппированным по предметам, брендам и ярлыкам. В ответе возвращаются общие данные по остаткам в разрезе групп товаров.

Метод помогает решать стратегические задачи. Используйте его, чтобы:

оценивать структуру запасов на уровне групп — понимать, какие бренды или предметы занимают больше всего места на складе и куда уходят основные оборотные средства
планировать закупки для целых групп на уровне брендов или предметов, не углубляясь в каждый артикул
сравнивать динамику между группами — отслеживать, какие группы товаров продаются лучше, а какие хуже
Данные по товарам
Метод POST /api/v2/stocks-report/products/products возвращает детализацию по каждому товару в отдельности. В ответе можно увидеть не только количество остатков на складах, но и ключевые метрики: заказы, выкупы, оборачиваемость, текущие цены и расчётный статус доступности товара.

Метод помогает решать задачи регулярного контроля ассортимента. Используйте его, чтобы:

оценивать финансовую эффективность. Метод позволяет рассчитать стоимость остатков и спланировать объём продаж если запасов меньше, чем обычно
контролировать оборачиваемость. Вы можете отследить, как быстро товары покидают склад, и на основе этих данных скорректировать стратегию закупок
анализировать, как изменение стоимости или акции влияют на спрос и остатки
Данные по размерам
Метод POST /api/v2/stocks-report/products/sizes возвращает детализированную информацию об остатках по каждому размеру конкретного товара. В зависимости от параметра includeOffice вы можете получить:

общую картину по размерам
детальное распределение остатков по отдельным складам и регионам
Используйте метод, чтобы:

оценивать, какие размеры представлены на складах, а каких не хватает для формирования полного ассортимента
проверять, равномерно ли распределены размеры по федеральным округам, чтобы не терять продажи в регионах из-за отсутствия нужного размера
принимать решения о перемещении партий между складами, чтобы устранять локальный недостаток размеров или сокращать расходы на хранение при переизбытке
сравнивать, какие размеры продаются быстрее, а какие долго хранятся на складах, чтобы корректировать закупки и ценовую политику
контролировать упущенные продажи с помощью полей lostOrdersCount и lostBuyoutsCount. Они показывают, какой размер заканчивается чаще всего
оптимизировать планирование поставок. Данные об остатках на конкретных складах помогают сформировать список товаров в поставке с учётом реальной потребности по каждому размеру
• Если товар неразмерный — его единственный размер "0" — данные по складам приходят без разбивки по размерам
• Данные по всем складам продавца приходят в агрегированном виде — по всем сразу, без детализации по конкретным складам — эти записи будут с "regionName":"Маркетплейс"
• Фильтр "stockType":"mp" объединяет модели FBS, DBW, DBS и Самовывоз

Данные по складам
Метод POST /api/v2/stocks-report/offices показывает распределение товаров по складам и федеральным округам. В ответе видно, сколько единиц товара суммарно хранится в каждом регионе с детализацией по конкретным складам.

Метод помогает решать логистические задачи. Используйте его, чтобы:

анализировать, насколько товары сбалансированы по регионам. Это позволяет избегать ситуаций, когда в одном округе избыток остатков, а в другом — недостаток
анализировать оборачиваемость на уровне регионов с помощью поля saleRate. Оно показывает, как быстро товары продаются в каждом округе. С его помощью вы можете корректировать объёмы поставок по регионам под реальный спрос
наблюдать за товарами в пути с помощью полей toClientCount и fromClientCount. Они позволяют отслеживать, сколько товаров находится в пути к покупателям или возвращаются обратно на уровне складов и регионов
• Если товар неразмерный — его единственный размер "0" — данные по складам приходят без разбивки по размерам
• Данные по всем складам продавца приходят в агрегированном виде — по всем сразу, без детализации по конкретным складам — эти записи будут с "regionName":"Маркетплейс"

CSV-отчёты Аналитики остатков
Для работы с большими объёмами данных используйте специализированные CSV-отчёты — они позволяют выгрузить данные по всем артикулам с фильтрами по датам, складам, товарам и так далее, так же как и с помощью методов Истории остатков:

STOCK_HISTORY_REPORT_CSV — статистика остатков
STOCK_HISTORY_DAILY_CSV — история остатков по дням
Данные в CSV-отчётах по остаткам представлены максимум за 3 месяца и доступны без подписки Джем

Чтобы получить CSV-отчёт, соблюдайте порядок действий:

scheme
Шаг 1. Создайте задание на генерацию
Выполните запрос метода POST /api/v2/nm-report/downloads. В теле запроса укажите:

UUID отчёта
тип — например, STOCK_HISTORY_REPORT_CSV
период
уровень детализации
фильтры
Шаг 2. Проверьте статус готовности
Отчёт формируется не сразу. Чтобы проверить статус генерации отчёта, используйте метод GET /api/v2/nm-report/downloads.

Когда статус сменится на SUCCESS, отчёт будет готов. Файлы хранятся 48 часов.

Если вы получили статус FAILED, отправьте запрос POST /api/v2/nm-report/downloads/retry, чтобы сгенерировать отчёт повторно

Шаг 3. Скачайте готовый отчёт
Готовый CSV-отчёт будет сгенерирован в ZIP-архив. Скачайте его с помощью метода GET /api/v2/nm-report/downloads/file/{downloadId}.

Как фильтровать данные
Методы Истории остатков собирают статистику по всем товарам продавца. В зависимости от задачи вы можете настроить выгрузку товаров с помощью фильтров:

currentPeriod — запрашиваемый период. Вы можете задать произвольный интервал в пределах доступных дат.
Как можно использовать: сравнить продажи в регионе до и после того, как на местном складе появился ваш товар. Это поможет понять, насколько увеличилась конверсия в заказ за счёт сокращения сроков доставки.
nmIDs — артикулы WB — отбор по конкретным товарам из вашего каталога.
Как можно использовать: вы готовите 10 товаров к распродаже через WB Продвижение. С помощью фильтра вы можете проверить остатки по каждому товару, чтобы не запустить трафик на товары в дефиците.
brandNames — бренды товаров.
Как можно использовать: вы расширили линейку бренда и хотите понять, как быстро новинки уходят со складов по сравнению со старыми позициями.
subjectIDs — предметы по классификации Wildberries.
Как можно использовать: вы решили убрать один из предметов из ассортимента из-за низкой прибыли. Фильтр поможет оценить сумму замороженных в этой категории средств перед распродажей остатков.
tagIDs — ярлыки продавца, которые можно указать в карточке товара.
Как можно использовать: у вас есть товары с ярлыком Чёрная пятница. Фильтр покажет, как быстро они уходят со складов. Так вы сможете вовремя пополнить запасы и не потерять прибыль во время распродаж.
skipDeletedNm — скрыть удалённые товары.
Как можно использовать: вы выгружаете остатки для инвентаризации. С помощью этого фильтра в отчёт не попадут удалённые карточки товаров.
stockType — тип складов хранения товаров: склады Wildberries wb или собственные склады продавца mp.
Как можно использовать: вы хотите понять, как быстро распродаются товары по разным моделям продаж. Фильтр "stockType":"wb" покажет остатки и оборачиваемость только по тем позициям, которые хранятся на складах WB. Фильтр "stockType":"mp" покажет остатки и оборачиваемость по позициям на складах продавца — он объединяет модели FBS, DBW, DBS и Самовывоз.
